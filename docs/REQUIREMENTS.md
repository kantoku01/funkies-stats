# ファンキーズ打撃成績アプリ 要件定義書

2026-10-12 · SHINYA ADACHI

> 原本: Claude Docs「ファンキーズ打撃成績アプリ 要件定義書」(https://claude.ai/artifact/JoNxbrhUd1FoB9FMCevDQR)。
> このファイルは開発用の写し。要件を変えるときは原本と両方を更新する。

## 概要・目的

試合ごとに1打席ずつ結果を記録し、シーズン成績はすべて自動集計するWebアプリ「ファンキーズ打撃成績」を作る。現在のスプレッドシート「ファンキーズ打撃成績」は、シーズン累計に毎週手で数字を足しているため、転記ミスが起きている。

- **記録の単位**:1試合 × 1選手 × 1打席。累計や率は保存せず、毎回ここから計算する
- **後からの修正**:過去の試合の参加者・打席結果を直せば、累計も自動で正しくなる
- **入力の流れ**:試合後にスマホで、①試合を作成 → ②参加者を登録 → ③選手ごとに打席結果を入力
- **見せ方**:今のシートと同じく、規定到達者をOPS順に並べ、その下に規定未達・助っ人を表示する

## 利用者と権限

閲覧はログイン不要で誰でも可能、編集はログインした編集者だけに限る。チームメンバーには閲覧用URLを共有する。

| 役割 | 対象 | できること | ログイン |
| --- | --- | --- | --- |
| 閲覧者 | チームメンバー全員 | 成績一覧・個人成績・試合結果の閲覧 | 不要 |
| 編集者 | Shinya+指名した数名 | 試合・参加者・打席結果・選手・背番号の登録と編集 | 必要 |

- 編集者の追加・削除は、管理画面からではなくSupabase上の編集者テーブルを直接編集する形で十分(人数が少ないため)
- 削除操作(試合・選手・参加者の削除)は確認ダイアログを必須にする

## 画面構成と操作フロー

画面は閲覧用4つと編集用4つ。トップページは成績一覧にする。

| 画面 | 対象 | 主な内容 |
| --- | --- | --- |
| 成績一覧(トップ) | 全員 | シーズン切替、チーム成績(試合数・勝敗・勝率・チーム打撃)、規定打席、選手別成績表 |
| 個人成績 | 全員 | シーズン累計+試合ごとの成績一覧(試合日・打席結果・打点・盗塁) |
| 試合一覧 | 全員 | 日付・対戦相手・スコア・勝敗の一覧、新しい順 |
| 試合詳細 | 全員 | スコア、参加者ごとの打席結果(1打席目、2打席目…)と打点・盗塁 |
| 試合作成・編集 | 編集者 | 日付・対戦相手・得点・失点・勝敗の入力 |
| 参加者登録 | 編集者 | 選手一覧からチェックで参加者を選ぶ。打順は任意入力 |
| 打撃入力 | 編集者 | 参加者ごとに打席結果をまとめて入力(次の章) |
| 選手管理 | 編集者 | 選手の登録・編集、シーズン別背番号の設定 |

### 試合後の入力フロー

1. 試合一覧の「試合を追加」から、日付・対戦相手・スコア・勝敗を入れて保存
2. 参加者登録画面に進み、出席した選手にチェック(助っ人も同じ一覧から選ぶ)
3. 打撃入力画面で、参加者を1人ずつ順番に入力し、最後の選手を保存したら試合詳細に戻る

3つの画面はどれも後から個別に開いて編集できる。参加者から外した選手に打席結果がある場合は、打席結果も一緒に消えることを確認ダイアログで伝える。

### 成績一覧の表示ルール

- 規定到達者をOPSの高い順に表示し、「規定未達」の見出しの下に規定未達の正規メンバー、その下に助っ人を表示
- 列見出しのタップで並べ替え可能(既定はOPS降順)
- スマホでは背番号・氏名の列を固定し、成績の列は横スクロール
- 表の上に「◯/◯時点」「規定打席 ◯◯」を表示

## 打撃入力画面

1人の選手の全打席をこの画面で続けて入力し、終わったら「次の選手へ」で切り替える。打席・打数・安打などの合計は打席結果から自動で決まるので、数字の手入力はない。

### 画面の構成(スマホ縦画面)

1. **ヘッダー**:背番号・氏名、進捗(例:3/12人目)、前の選手/次の選手ボタン
2. **打席結果ボタン**:タップするたびに打席が1つ追加される。片手で押せる大きさ(44px以上)で3列に並べる
   - 安打:単打、二塁打、三塁打、本塁打
   - 四死球・犠打:四球、死球、犠飛、犠打
   - アウト:凡退
3. **打席リスト**:追加した打席を「1打席目 単打 打点0」のように順番に表示。打点は0で表示し、各行の右端に大きめの+ボタン(44px以上)を置いて、その場ですぐ打点を足せるようにする。−ボタンと削除ボタンは誤タップを避けるため小さめにする。直前に追加した行はハイライトし、+ボタンが結果ボタンのすぐ下に来るようにする(打点0〜4)
4. **盗塁**:打席リストの各行で、打点の+ボタンの横に盗塁の+ボタンを並べる。打点と同じく最初は0で表示し、その打席で出塁したあとの盗塁数をすぐ足せる(盗塁0〜3)。代走など打席がないままの盗塁は、打席リストの下にある「打席外の盗塁 0 [+]」で入れる(0〜3)
5. **サマリー**:「4打数2安打1打点1盗塁」のように、入力内容をその場で表示
6. **参加者一覧**:画面下部に参加者を並べ、入力済み・未入力が分かるようにする。タップでその選手に移動

### 動作ルール

- 「凡退」は安打以外で打数に数える結果すべて(三振、ゴロ、フライ、失策出塁、野選など)
- 打席を間違えた場合は行を削除、または行をタップして結果を変更できる
- 選手を切り替えたときに自動保存。未保存のまま画面を離れようとしたら警告する
- 打席0のまま次へ進んでもよい(出席のみ・守備のみの選手)
- 並び順は打順が入っていれば打順順、なければ背番号順

### 入力チェック(警告のみ、保存は可能)

- 本塁打なのに打点0
- 犠飛なのに打点0
- 1人の打席数が7を超える

## 成績の計算ルール

表示項目は今のシートと同じ23項目で、すべて「初期値(2026年のみ)+アプリで入力した打席結果」から計算する。以下の式は2026年シートのチーム合計・宮川選手の数字で一致を確認済み(例:打数 868−99−29−6−2=732)。

### 打席結果から数えるもの

| 項目 | 数え方 |
| --- | --- |
| 打席 | 打席結果の件数 |
| 単打・二塁打・三塁打・本塁打 | 各結果の件数 |
| 四球・死球・犠飛・犠打 | 各結果の件数 |
| 打数 | 打席 − 四球 − 死球 − 犠飛 − 犠打 |
| 安打 | 単打 + 二塁打 + 三塁打 + 本塁打 |
| 塁打数 | 単打 + 二塁打×2 + 三塁打×3 + 本塁打×4 |
| 打点 | 各打席の打点の合計 |
| 盗塁 | 各打席の盗塁の合計 + 打席外の盗塁 |
| 出席 | 参加者として登録された試合数 |

### 率の計算

| 項目 | 計算式 |
| --- | --- |
| 打率 | 安打 ÷ 打数 |
| 出塁率 | (安打 + 四球 + 死球) ÷ (打数 + 四球 + 死球 + 犠飛) |
| 長打率 | 塁打数 ÷ 打数 |
| OPS | 出塁率 + 長打率 |
| 出席率 | 出席 ÷ 選手の試合数 |
| 打撃貢献率 | 出席率 × OPS |
| 勝率 | 勝 ÷ (勝 + 負)、引分は除く |

### 試合数と規定打席

- **チーム試合数**:そのシーズンの初期値の試合数 + アプリに登録した試合数
- **選手の試合数(正規メンバー)**:初期値の試合数 + 加入日以降かつ退団日以前のチーム試合数。途中加入の毛利選手(2026年は20試合)のようなケースを自動で扱える
- **選手の試合数(助っ人)**:出席数と同じ。よって助っ人の出席率は常に1.000
- **規定打席**:チーム試合数 × 1.2(2026年9/13時点で30試合 → 36打席)
- **規定到達の判定**:打席 ≥ 規定打席。助っ人は判定の対象外で、常に一覧の最下段

### 表示形式

- 率はすべて小数第3位まで四捨五入。1未満は先頭の0を省く(.333)、1以上はそのまま(1.034)
- 分母が0の場合は .000 と表示
- チーム合計は助っ人を含む全選手の合計(シートのチーム打席868は全21人の合計と一致)
- シーズンの区切りは次の「シーズンの切り替え」を参照

### シーズンの切り替え

年が変わると自動で新しいシーズンが始まる。切り替えのための操作は不要。

- シーズン = 暦年(1/1〜12/31)。試合日の年でどのシーズンの試合かを決める
- 新シーズンは試合数・勝敗・全選手の成績が0から始まる。前のシーズンの成績はシーズン切替でいつでも見られる
- 成績一覧は、試合が1つでも登録された最新のシーズンを既定で表示する(年明け直後は前年を表示し、初戦を登録すると新年に切り替わる)
- 背番号は前シーズンの番号を自動で引き継ぎ、変わった選手だけ選手管理で直す
- 初期値(season_baselines)は2026年だけに使い、2027年以降は持たない

## データ構造

保存するのは「誰が・どの試合で・何打席目に・どんな結果だったか」だけで、累計や率は持たない。テーブルは8つ。

| テーブル | 主なカラム | 補足 |
| --- | --- | --- |
| players(選手) | id, full_name, kind, joined_on, left_on, created_at | full_nameはフルネーム必須。kindは regular(正規)/ guest(助っ人)。left_onは退団日(空なら在籍中) |
| season_numbers(シーズン別背番号) | season, player_id, number | (season, player_id)で一意。numberは文字列("0"と"00"を区別するため)。助っ人は未設定で「助」と表示 |
| games(試合) | id, game_date, opponent, team_score, opponent_score, result, memo | resultは win / lose / draw。得点・失点・対戦相手は任意。seasonはgame_dateの年から求める |
| game_participants(参加者) | game_id, player_id, batting_order, extra_stolen_bases | (game_id, player_id)で一意。batting_orderは任意。extra_stolen_basesは打席外の盗塁(代走など、初期値0) |
| plate_appearances(打席) | id, game_id, player_id, seq, result, rbi, stolen_bases | seqは何打席目か。resultは single / double / triple / home_run / walk / hbp / sac_fly / sac_bunt / out。rbiは0〜4、stolen_basesは0〜3 |
| season_baselines(選手の初期値) | season, player_id, games, attendance, pa, singles, doubles, triples, home_runs, walks, hbp, sac_flies, sac_bunts, rbi, stolen_bases | 移行用。打数・安打・塁打数は持たず、他と同じく計算で出す |
| team_season_baselines(チームの初期値) | season, games, wins, losses, draws, as_of | 移行用。as_ofは初期値の時点(2026-09-13) |
| editors(編集者) | user_id, display_name | Supabase Authのユーザーと紐づけ |

- plate_appearancesとgame_participantsは、参加者を削除したら打席も消える(外部キーで連動削除)
- 集計はSQLのビューまたはアプリ側の関数で行い、計算ロジックは1か所にまとめてテストを書く
- RLS:全テーブルで読み取りは匿名ユーザーに許可、書き込みはeditorsに登録されたユーザーだけ

## 既存データ移行

2026年シーズンだけを移行し、スプレッドシートの9/13時点の累計を「初期値」として取り込む。2025年分は移行しない。試合ごとの内訳はないので、初期値は選手ごと・チームごとに1行で持つ。

- **チーム初期値**:30試合、16勝14敗0分、時点 2026-09-13

- **氏名**:シートは名字のみなので、取り込み前にフルネームを埋める(「森 陽」「森 郁」もフルネームに置き換え)

## 技術構成・非機能要件

Next.js(App Router)+ Supabase + Vercel で構築し、すべて無料枠で運用する。

| 領域 | 採用技術 | 用途 |
| --- | --- | --- |
| フロントエンド | Next.js + TypeScript + Tailwind CSS | 画面、成績計算ロジック |
| データベース | Supabase(PostgreSQL) | 全データの保存、RLSによる権限制御 |
| 認証 | Supabase Auth(メール+パスワード、またはメールリンク) | 編集者のログイン |
| ホスティング | Vercel | 公開URLの提供 |

- **スマホ優先**:iPhone Safariの縦画面を基準に設計。ボタンは44px以上、主要操作は片手で届く画面下部に置く
- **UIは日本語のみ**
- **ホーム画面に追加**できるよう、アプリ名とアイコンを設定(PWA対応は任意)
- **バックアップ**:成績一覧と打席データのCSV書き出し機能を編集者向けに用意する
- **テスト**:成績計算関数には単体テストを書き、移行データでシートと同じ値になることを確認する

## 対象外と未決事項

今回はスプレッドシートと同じ項目だけを扱い、投手成績や三振・得点・失策は入れない。

**対象外**

- 投手成績、守備成績
- 三振・得点・失策・打撃妨害の個別記録(三振や失策出塁は「凡退」に含める)
- 2025年以前のデータ
- 試合中のリアルタイム入力

**未決事項**

- [ ] 移行対象21人のフルネーム
- [ ] 9/14〜10/12に行った試合の有無と、その試合のスコア
- [ ] 編集者にする人(Shinya以外)
- [ ] 公開URL(例:funkies-stats.vercel.app)

## Claude Codeでの開発ステップ

計算ロジックとデータ移行を先に固め、その後に画面を作る順番で進める。各ステップの終わりに動作確認してから次へ進む。

1. **土台**:Next.jsプロジェクト作成、Supabase接続、全テーブルとRLSのマイグレーション、編集者ログイン
2. **計算ロジック**:成績計算関数と単体テスト。移行CSVを取り込み、チーム打率.272・OPS.778などシートと一致することを確認
3. **成績一覧**:トップページ(シーズン切替、規定到達/未達/助っ人の区分、並べ替え、列固定)
4. **選手管理**:選手とシーズン別背番号の登録・編集
5. **試合と参加者**:試合一覧・作成・編集、参加者登録
6. **打撃入力**:選手ごとの打席入力画面、自動保存、入力チェック
7. **閲覧画面の仕上げ**:試合詳細、個人成績、CSV書き出し
8. **公開**:Vercelにデプロイし、iPhoneで実際の試合1つ分を入力して確認

## 実装上の決定事項(ステップ1で合意)

要件定義書からの補足・変更点。

- `editors` は匿名ユーザーに公開しない(ログインした本人が自分の行を読めるだけ)
- 選手の削除は、試合の記録があると止める(`on delete restrict`)。辞めた選手は退団日で扱う
- 認証はメール+パスワード。新規登録は無効にし、編集者のアカウントはダッシュボードから作る
- 背番号は行をコピーせず、「そのシーズン以前で最新の番号」を表示して引き継ぐ
- 集計はアプリ側の TypeScript 関数(`src/lib/stats`)1か所で行う
